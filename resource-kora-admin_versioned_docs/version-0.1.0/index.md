Command-driven admin menu for kora_core/kora_lib. There is exactly one entry point
for every privileged action: a chat command. The NUI menu (`/admin`) is not a
parallel code path — after collecting a target and some parameters, it builds
the exact command string a human would type and runs it with
`ExecuteCommand`. Whether an action was typed or clicked, the same permission
check, argument parsing, handler, audit log write, and notification run —
there is nothing to keep in sync between the two UIs because there is only
one implementation.

## Requirements

- [kora_lib](https://qbcore2.github.io/kora_lib/) — must load before kora_core/kora_sql
- [kora_core](https://qbcore2.github.io/kora_core/)
- [kora_sql](https://qbcore2.github.io/kora_sql/)

## Installation

`server.cfg`, in dependency order:
```
ensure kora_sql
ensure kora_lib
ensure kora_core
ensure kora_vehiclekeys
ensure kora_admin
```
kora_admin creates its own `admin_logs` table at startup from `server/schema.lua`
(`Kora.sql.ensureTables`) — no manual schema import needed.

Grant permission roles with ACE principals in `server.cfg` (`Support <
Moderator < Admin < Owner`, cascading):
```cfg
add_ace identifier.license:XXXX kora_core.support allow
add_ace identifier.license:YYYY kora_core.moderator allow
add_ace identifier.license:ZZZZ kora_core.owner allow
add_principal identifier.license:XXXX group.support
add_principal identifier.license:YYYY group.admin
add_principal identifier.license:ZZZZ group.owner
```

All checks go through kora_lib's central permission gateway. ACEs are always
active, including the `group.admin` ACE. Discord roles can optionally add a
tier through `Config.permissions.discordRoles`:

```lua
discordRoles = {
    moderator = { 'Moderator' },
    admin = { '123456789012345678' }, -- role IDs are preferred
    owner = { 'Owner' },
}
```

Discord grants require kora_lib's Discord bot and guild convars. Missing or stale
role data fails closed without affecting ACE authorization.

## Usage examples

Almost every action below can be typed in chat by an admin, clicked in the
`/admin` NUI, or run programmatically from another resource with
`ExecuteCommand` — the server console is exempt from the permission check
entirely, so a trusted server-side script can call any command directly.

The menu sidebar is split into five focused workspaces: **Players**, **Reports**,
**My Tools**, **Server**, and **Development**. Tabs inside those pages keep
related actions together without turning every tool into another sidebar row.
Selecting an online player replaces the list with tabbed profile, player-tool,
moderation, economy/item, role/access, and advanced views; Back returns to the
live player browser. **Copy Player Info** copies the visible profile fields;
platform identifiers and permission level are included only for admins.
The owner-only **Server → Configuration** tab opens the kora_lib configuration
workspace described below.

### Give a player money and an item
```
-- chat, typed by an admin (or generated by the /admin NUI)
/givemoney 3 cash 500 event-reward
/giveitem 3 water_bottle 5
```
```lua
-- server, e.g. an event-reward script running as console
ExecuteCommand('givemoney 3 cash 500 event-reward')
ExecuteCommand('giveitem 3 water_bottle 5')
```

### Vehicle keys
Vehicles created through `/car` and `/veh` automatically grant session keys
to the player receiving the vehicle. `/givekeys` is not an admin command: it
belongs to `kora_vehiclekeys` (a player hands over keys they hold). To grant
or revoke keys by plate, use that resource's admin commands
`/addkeys <id> <plate>` and `/removekeys <id> <plate>`.

### Teleport, noclip, spectate
```
/tpm                  -- teleport to your waypoint (ground-snapped)
/goto 3               -- teleport to player 3
/bring 3              -- bring player 3 to you
/noclip               -- toggle a free-fly camera
/spectate 3           -- spectate player 3; /spectate with no id stops
```

### Kick or ban a player from a moderation script
```lua
-- server, e.g. an anti-cheat resource flags a player and hands off to kora_admin
RegisterNetEvent('anticheat:flagged', function(targetSrc, reason)
    ExecuteCommand(('kick %d %s'):format(targetSrc, reason))
    -- or, for a persistent, offline-capable ban:
    ExecuteCommand(('ban %d 7d %s'):format(targetSrc, reason))
end)
```

### Heal, revive, freeze, god/development mode
```
/heal me              -- or just /heal, or /heal 3 for another player
/revive 3             -- revive a downed player (clears the death state)
/freeze 3 true         -- freeze player 3 in place; /freeze 3 false to release
/god me true            -- toggle your own god mode; targeting others needs admin
/devmode me true        -- god mode + paused needs + fast walk; others need admin
```

### Set job/gang and spawn vehicles or entities
```
/setjob 3 police 2    -- set player 3's job to police, grade 2
/setgang 3 ballas 1
/car zentorno          -- spawn a vehicle and get in
/veh 3 zentorno         -- spawn a vehicle for player 3
/givevehicle 3 sultan STAFF01 -- add a persistent personal garage vehicle
/entity a_m_m_skater_01 -- spawn a static local ped in front of you
/entityfor 3 prop_barrel_02a -- spawn a static local prop for player 3
/deleteentity           -- delete your last admin-spawned entity
```

In the admin menu, **My Tools → Vehicles → Spawn from Code** uses the same
`/car` command and accepts a plain spawn code: enter `outlaw`, `zentorno`, or
any valid streamed addon vehicle model. **Browse Vehicle Catalogue** is a
separate searchable quick-pick list of common vanilla vehicles; it is not an
allow-list.

For a selected player, **Spawning → Add Personal Vehicle** saves a vehicle to
their garage database record. Enter a model and a unique plate containing 1-15
letters or numbers. The catalogue variant provides the same operation with a
searchable vehicle picker. The chat equivalent is
`/givevehicle <id> <model> <plate>`; the player must be online.

**Entities → Spawn Ped / Prop** accepts any valid ped or prop model. These
spawns are local to the recipient and static, which makes them safe for
testing; use **Delete My Last Spawned Entity** to remove the recipient's most
recent one. Vehicle models use the Vehicle commands so their spawn remains
networked.

### Capture a Medal clip

The **Development → Medal Clips** tab saves a configured highlight from the
local Medal recorder of the admin who clicks it. Generate a public key and
submit the same event IDs through [Medal's Auto-Clipping
builder](https://medal.tv/developer/auto-clipping), then add this replicated
setting to `server.cfg`:

```cfg
setr kora_admin_medal_public_key "your-public-key"
```

Configure one or more entries in `Config.medal.events`; each becomes a menu
button with its own event ID, display name, clip duration, and capture delay.
Medal must be installed and running on the clicking admin's PC. The menu shows
whether the local recorder accepted the request and gives specific guidance
for an invalid public key or event.

### Edit registered resource configuration

Owners can open the Configuration workspace from **Server → Configuration**
in `/admin`, or directly with:

```text
/config
```

The workspace lists only first-party or third-party resources that explicitly
registered a kora_lib schema. It shows each setting’s scope, saved value, running
value, and either **Applies now** or **Restart required**. Saving writes the
owning resource’s `config.local.lua`; it never reformats or reorders that
resource’s authored `config.lua`. Reset removes the in-game override and
returns to the documented default immediately for a live setting, or after a
resource restart otherwise.

The editor never exposes sensitive fields, server.cfg/convars, database-owned
records, runtime state, or executable values. Successful saves and resets are
recorded in `admin_logs` as `config.commit` and `config.reset`. The permission
is `Config.configEditor.level`, which defaults to `admin`.

See kora_lib’s [configuration guide](https://qbcore2.github.io/kora_lib/modules/config/docs.html)
to add schemas, client/server scopes, live handlers, or a migration bridge to
another resource.

### Read the audit trail from another resource
```lua
-- server, e.g. a staff-dashboard resource querying kora_admin's own table via kora_sql
local rows = Kora.sql.query(
    'SELECT * FROM `admin_logs` WHERE `action` = ? ORDER BY `created_at` DESC LIMIT 20', { 'ban' })
for _, row in ipairs(rows) do
    print(row.actor_name, 'banned', row.target_name, row.details)
end
```

## API reference

kora_admin has no `exports` — the whole surface is chat commands registered
through `Kora.commands.add`, plus internal `kora_admin:client:*`/`kora_admin:server:*`
events used to relay a command's effect to the right client. Most commands
accept an `[id]` argument that defaults to the caller, or the literal word
`me` — see `Admin.resolveTarget` (`server/target.lua`). Commands marked
**(no me)** use an offline-capable resolver instead.

### Player / info — `support`
```
/admin                                    -- open the NUI menu
/players [search]                         -- list online players
/permission [id=me]                       -- show a player's permission level
```

### Moderation — `moderator`
```
/warn <id> <reason>
/warnings <id>                            -- warning history
/kick [id=me] [reason]
/freeze <id> <true|false>
/kill <id>
/heal <id>                               -- also fills hunger/thirst (Config.heal.restoreNeeds)
/revive <id>
/god [id=me] [true|false]                 -- targeting another player needs admin
/devmode [id=me] [true|false]             -- targeting another player needs admin
/invisible [id=me] [true|false]           -- targeting another player needs admin
```

### Moderation — `admin`
```
/ban <target> <duration|perm> <reason>    -- (no me) online id, citizenid, or name
/unban <license|banId>                    -- (no me) preserves ban history
```

### Teleport / noclip / spectate — `moderator`
```
/goto <id>          /bring <id>          /sendback <id>
/tpm                 /tpback
/tpcoords <x> <y> <z>
/tpcoords vec3(<x>, <y>, <z>)
/tpcoords vector4(<x>, <y>, <z>, <heading>)
/spectate [id]       -- omit id to stop
```

### Noclip — `admin`
```
/noclip
```

### Player reports
```
/report <type> <message>                 -- player, bug, exploit, gameplay, question, other
/reportstatus <id>                       -- reporter or staff
/reportreply <id> <message>              -- reporter or staff
/reports [status] [type] [page]          -- support+
/reportclaim <id>                        -- support+
/reportresolve <id> [resolution]         -- support+
/reportdismiss <id> [reason]             -- support+
/reportreopen <id> [reason]              -- support+
```

The admin menu's **Reports** workspace shows persistent reports with filters
for status, type, reporter, and page. Selecting one opens separate Overview,
Manage, and Online Reporter tabs. Open reports can be claimed, replied to,
resolved, or dismissed; closed reports can be reopened. When the reporter is
online, staff also get teleport, bring, send-back, and spectate shortcuts.

### Selected-player appearance — `admin`
```
/clothingmenu <id>
/barbermenu <id>                         -- chooses barber/hairdresser for the model
/tattoomenu <id>
```

These commands open a free, one-use kora_clothing session for the selected
player. The authorization is created server-to-server and consumed by that
player's token-authenticated clothing request; clients cannot mint it.

### Economy — `admin`
```
/givemoney <id> <account> <amount> [reason]
/removemoney <id> <account> <amount> [reason]
/setmoney <id> <account> <amount> [reason]
/giveitem <id> <item> [amount] [infoJson]
/removeitem <id> <item> [amount]
/clearinventory <id>
```

### Job / gang — `admin`
```
/setjob <id> <job> [grade]
/setgang <id> <gang> [grade]
```

### Job / gang — `moderator`
```
/setduty [id=me] [true|false]
```

### Vehicle — `admin`
```
/car <model>            -- spawn and get in
/veh <id> <model>       -- spawn for a player
/givevehicle <id> <model> <plate> -- add a persistent personal garage vehicle
/dv [radius]             -- delete the vehicle you're in, else the nearest one (Config.dv); [radius] deletes all in range, capped
```

### Vehicle — `moderator`
```
/fix                     -- repair the vehicle you're in
```

### Entities — `admin`
```
/entity <model>           -- spawn a static local ped or prop in front of you
/entityfor <id> <model>   -- spawn one for a player
/deleteentity             -- delete your last admin-spawned entity
```

### Developer — configurable, default `admin`
```
/entitypicker                 -- inspect aimed entity; H copies its actual model name, X closes
/devplacement <model>          -- place any valid ped, vehicle, or object; copy its transform
/devzone <box|sphere|poly>     -- capture and copy a kora_lib zone definition
```
The selected player's **Development** group toggles kora_core development mode
for yourself or another player through `/devmode`. With
`Config.developer.requireDevMode = true` (the default is `false`), creator commands reject until the
caller enables their own development mode. Neither creator persists its
preview or registers a live zone.

### World / server — `admin`
```
/announce <message>
/weather <type>
/time <hour> [minute]                     -- /time 21, /time 8 30
/time <preset>                            -- /time morning|noon|night
/adminlog [action] [target] [page]
```
`/time` takes either a whole-number hour (`0-23`) with an optional minute
(`0-59`), or one of the words in `Config.world.timePresets` -- the same words
the admin menu's **Set Time** selector offers as one-click buttons. The preset
word is what travels to the server, so its hour and minute come from
`config.lua` and are range-checked there like any typed value; an unknown word
or an out-of-range number is refused with a reason rather than clamped. In the
menu, the hour/minute inputs appear only behind **Custom**.

### World / server — `moderator`
```
/serverinfo
```

### Self / utility — `moderator`
```
/aduty                   -- toggle admin on-duty status
/coords                  -- copy your current coordinates to the clipboard
/health [percentage]     -- 0-100%, reviving first if dead
/armor [value]
/sethunger <id> <0-100>  -- admin
/setthirst <id> <0-100>  -- admin
```

### Privileged — `owner`
```
/config
/restartresource <name>
/setpermission <id> <role>                -- unrestricted runtime only
/revokepermission <id> <role>             -- unrestricted runtime only
```

### Temporary access — `admin` by default
```
/granttempaccess <id> <role> <minutes>
/revoketempaccess <id> <role>
```
Temporary grants are memory-only, expire automatically, and are configured by
`Config.permissions.temporaryGrant`.

## Config highlights (`config.lua`)

`Config.permissions.roles` (the default `Support < Moderator < Admin < Owner`
ladder), optional `discordRoles`, `temporaryGrant`, and
`principalIdentifier` (must match kora_core's own `Config.identity.primaryIdentifier`,
default `license`); `Config.ban.durationUnits`/`durationWords` (`30m`, `2h`,
`7d`, `1w`, or `perm`); `Config.teleport` fade/collision timing and
`waypointLaunchHeight`/`groundZAttempts`/`groundZRetryDelay` (the ground-snap
algorithm used by `/tpm`, ported from txAdmin's own); `Config.noclip.baseSpeed`/`fastMultiplier`/`slowMultiplier`, and `adMode` (`strafe` default: A/D slide sideways relative to the camera; `turn`: A/D yaw the view, at `turnSpeed` degrees/frame);
`Config.world.weatherTypes`, `timePresets` (the ordered `/time` preset words
and their hour/minute -- change these to change what `night` means here) and
`syncOnPlayerLoaded`; `Config.vehicle.spawnOffset` and
`Config.entity.spawnOffset`; `Config.developer.menuLevel` and `requireDevMode`;
`Config.entityPicker.maxDistance`, `copyKey`, and `closeKey`;
`Config.medal` for the public key, menu permission, timeout, and clip events;
`Config.audit.pageSize`; `Config.keybind` for the default `/admin` keybind
(`F7`); and `Config.configEditor.level` for the admin configuration
workspace. kora_lib-managed edits are server-specific `config.local.lua`
overrides, not edits to this documented file. The optional Discord role map is
declared in `server/config.lua`, is server-only, and can be edited only by an
owner through the workspace.
